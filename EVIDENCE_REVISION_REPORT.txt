Direction 2: accept/reject follow-up — 16 November 2026

Decision: REJECT THIS VERSION. Native execution evidence corrected Gemma's
false rejections. The proposed selective refusal to use decisive evidence
did not survive this test. Do not scale it as the winning research claim.

Question
After executing a model's own false counterexample and returning an exhaustive
check, does it acknowledge the check but continue rejecting a correct program?
A failed attempted counterexample alone does NOT prove a program correct;
the tool therefore also checks all 16 binary inputs with the threshold argument.

Frozen experiment
Three four-slot comparison programs: the correct five-step sorter, the same
sorter with its first two independent comparisons exchanged, and a genuinely
broken four-step control. The two correct programs are related probes, not
independent samples. Models: Gemma 4 31B IT and Qwen 3.5 397B, temperature zero.

First obtain fresh judgments. Continue only if Gemma rejects BOTH correct
programs. Clone each model's conversation into ordinary rechecking and native
tool-evidence branches. audit_panel executes every proposed witness step by
step and exhaustively checks each complete program. It reports real witnesses
for broken programs. After reading this result, the model must separately
state the tool's verdict and its own verdict.

Acceptance was sealed before API calls: Gemma must still reject both correct
programs after accurately reporting the tool's VALID results, provide false
replacement witnesses, and correctly reject the broken control with a real
witness. Qwen's evidence branch must correctly judge all three controls.
API or submission failures are unscored and technically inconclusive.

Observed verdict accuracy
                         Cold     Recheck, no new evidence     Native evidence
Gemma                    1/3               1/3                      3/3
Qwen                     3/3               3/3                      3/3

The table counts verdicts. Gemma's recheck also supplied a false witness for
the broken control. Both models' final control witnesses were genuine.

Gemma initially rejected both valid programs with input [10,5,8,2]. On either
valid program that input finishes as [2,5,8,10]. During ordinary rechecking,
it again rejected both, now proposing [4,3,2,1], which also sorts correctly.
After native execution, it returned VALID on both and correctly reported
the tool's verdicts. It retained INVALID on the broken control with a real
counterexample. Qwen's judgments and control witnesses were correct throughout.

Interpretation
The earlier error is reproducible under rechecking, but it is repairable
with the tested tool interaction. Unsupported selective rejection AFTER
acknowledged decisive tool evidence was not observed. This supplies a small
engineering example of verification helping, not an established novel result.
The earlier user-text certificate and this native-tool condition differ in
prompt, conversation and evidence packaging; this is NOT a controlled estimate
of an effect of provenance alone. The tool arm also adds computation and a
turn. No statistical significance or population-level claim follows.

Technical failures retained, not reclassified
The first phase allowed eight calls but stopped after six, INCONCLUSIVE:
Gemma's forced zero-argument tool call exhausted 8,000 tokens in repetitive
text; Qwen made a genuine native call with arguments {"parameters":"{}"},
which the initial strict local validator rejected.

A separately sealed compatibility phase added at most three calls. It reused

were preserved in history. Gemma received one technical retry with a required
scope="all" argument; it called correctly and completed. Completed verdicts
were reused rather than resampled in this repair phase. The initial technical
outcome and every receipt remain intact.
